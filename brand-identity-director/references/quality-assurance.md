# Critique and quality assurance

R1 §4.3 and R2 §5 supply scale, single-color, blur, and five-second recall diagnostics (`REPORT-H`). None has a universal pass threshold or demonstrates market success. This package's automation creates stimuli and records technical observations; it does not judge human perception.

## Review in layers

1. Strategy: Does it express the brief's decision criteria and preserve required equity? Which assertions are only hypotheses?
2. Distinctiveness: Compare actual nearest category neighbors in name, composition, contour, imagery, and system behavior. A fresh-looking mark is not proof of originality or clearance.
3. Craft: Inspect contours, spacing, hierarchy, balance, typography, positive/negative space, and consistency.
4. Function: Test real-size applications, background variants, long names, languages, contrast, and constraints.
5. Production/rights: Verify exports, licenses, printer requirements, asset inventory, and unapproved claims.

Use [scorecard](../templates/critique-scorecard.md); record observation → consequence → recommendation → retest. Prioritize blockers, significant failures, and polish separately. Do not bury a safety, rights, or legibility blocker inside an attractive average score. Assign numeric weights only before comparison and explain their subjectivity. N/A should not become a zero.

## Diagnostic matrix

Render symbol/micro artwork at 16, 24, 32, 48, 64, 128, and 256 px longest edge, plus any actual minimum. Wide wordmarks need a different size range; 16 px longest-edge is not a universal wordmark requirement. Inspect at 100% pixel size, not only enlarged. Test light/dark/neutral backgrounds, genuine one-color/reversed exports, grayscale, and silhouette. A foreground-only monochrome derivative can merge intentional white detail; inspect it and create a deliberate variant rather than claim automatic conversion succeeded.

Blur is a comparative macro-form exercise; record radius relative to image size. It is not a pass/fail memorability test. A five-second exposure can be used as a small formative recall activity: define participant criteria, exposure and delay, comparable stimuli/order, response task, and coding before the test. Distinguish short-term recall from long-term recognition and prior familiarity. Report actual counts and limitations. Never say users passed a test that only an agent or script ran.

## Refinement and acceptance

Keep a versioned baseline, target only the high-priority findings, and compare the same contexts afterward. Accept when agreed criteria are satisfied and evidence is sufficient for the intended scope. Mark deferred items with owner and next action. Delivery can be a review package while printer proofs or legal review remain outstanding; call it that. Final production acceptance requires the relevant checks, not just an SVG exit code.
